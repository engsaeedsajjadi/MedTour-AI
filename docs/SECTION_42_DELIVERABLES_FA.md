# بخش ۴۲ — Deliverables / خروجی‌ها و بسته تحویل

## وضعیت واقعی
فهرست ساختاریافته اقلام تحویل، ابزار اعتبارسنجی و تست‌های مصنوعی تهیه شده‌اند. **بسته تحویل نهایی تأییدشده هنوز تولید نشده است**؛ فایل‌های PRهای ۲۷ تا ۴۱ نیز روی شاخه اصلی ادغام نشده‌اند.

## تحویل این مرحله
- `docs/section42_delivery_manifest.json`: فهرست فایل‌ها و پوشه‌های موردنیازِ نسخه توسعه (backend/frontend، قفل وابستگی‌ها، Compose، Dockerfile، Alembic، تست، CI، راهنما، مستندات امنیتی و نقطه ورود ربات تلگرام).
- `scripts/section42_verify_delivery.py`: بررسی خواندنیِ وجود اقلام و رد مسیرهای خارج از مخزن. این ابزار نه داده پزشکی می‌خواند و نه بسته Production منتشر می‌کند.
- `backend/tests/test_section_42_delivery.py`: سناریوهای اقلام مفقود، مسیرهای نامعتبر و تفکیک فهرست تحویل از پذیرش Production.

## تست صرفاً پس از یکپارچه‌سازی و روی سیستم خودت
```powershell
python scripts/section42_verify_delivery.py
cd backend
python -m pytest -q tests/test_section_42_delivery.py
```

## موارد باقی‌مانده برای تحویل کامل پرامپت
1. ادغام PRهای مستقل و رفع تعارض، به‌ویژه زنجیره Migration و تست Backend/Frontend.
2. فایل release manifest نسخه‌دار با commit SHA، image digest، SBOM و نتایج CI و تأیید بدون افشای secrets.
3. بسته ۳۰ سند/Artifact طبق پرامپت اصلی پس از بازبینی متن الزام‌ها و تأیید حضور هر مورد.
4. راهنمای نصب ویندوز، نسخه‌بندی، ارتقا، پشتیبان‌گیری، بازیابی و rollback که روی محیط ایزوله واقعاً آزمایش شده باشد.
5. تکمیل ربات تلگرام بعد از پایان و ادغام بخش‌ها مطابق ترتیب موردنظر کارفرما.
6. تأیید امنیت، بالین، حریم خصوصی، قرارداد ارائه‌دهنده‌ها و تست واقعی عملیاتی قبل از پذیرش بیمار.

**هشدار:** وجود فایل‌ها، موفقیت تست مصنوعی یا ثبت Pull Request به‌تنهایی به معنای آماده بودن محصول برای بیمار واقعی نیست.

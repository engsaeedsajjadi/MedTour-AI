# بخش ۲۹ — پرداخت‌ها و امور مالی (Finance & Payments)

## وضعیت تحویل
**توسعه کنترل‌های تطبیق مالی بر مبنای اسناد دستی تکمیل شد؛ سیستم هنوز درگاه پرداخت یا دفتر کل حسابداری تولیدی نیست.** تراکنش‌ها، اسناد و مانده‌ها صرفاً برای تست با داده مصنوعی مجازند.

### وضعیت قبل از بخش ۲۹
مسیر `POST /api/v1/finance/entries` در پروژه موجود بود و فقط به admin اجازه ثبت سند دستی با مرجع و جلوگیری از تکرار در Tenant را می‌داد. ثبت کارمزد ارجاع نماینده به‌دلیل نیاز به مجوز مستقل ممنوع است.

### قابلیت‌های افزوده
- `GET /api/v1/finance/reconciliation?case_id=<ID>`: خلاصه دریافتی، استرداد، هزینه و مانده خالص به تفکیک ارز، فقط مدیر Tenant.
- `GET /api/v1/finance/cases/{case_id}/quote-comparison`: فهرست پیشنهادهای مالی پرونده بدون ادعای بدهی قطعی.
- کنترل 404 برای شناسه پرونده دیگران، 403 برای نقش فاقد دسترسی، سقف سخت ۲۰۰۰ سطر در گزارش، 409 در صورت حجم بیش از حد بدون ارائه جمع ناقص.
- جلوگیری از جمع‌زدن USD و EUR، عدم استفاده از FX تخمینی یا قیمت پیشنهادی برای تأیید دریافت.
- حذف `agency_fee` از محاسبه مانده به دلیل نبود تأیید حقوقی آن.
- هیچ مسیری پرداخت انجام نمی‌دهد، به درگاه بانکی وصل نمی‌شود، وضعیت booking را تغییر نمی‌دهد یا گردش مالی را به‌عنوان تسویه بانکی اعلام نمی‌کند.

### تست‌های ایجادشده
`backend/tests/test_section_29_finance.py` سناریوهای چند ارز، جمع خالص، مرزبندی Tenant، خطا برای گزارش ناقص و محدودیت نقش را پوشش می‌دهد. **اجرای تست در این جلسه هنوز اثبات نشده**.

```powershell
git fetch origin
git switch feature/section-29-finance-controls
docker compose up -d --build
docker compose exec api pytest -q tests/test_section_29_finance.py
```

### موارد لازم برای تکمیل نسخه قابل فروش
1. طراحی و migration دفتر دوبل append-only با ثبت اصلاح از طریق اسناد معکوس، period close، تفکیک حساب‌های دریافتنی/پرداختنی، تطبیق بانکی و آزمون concurrent double-entry.
2. صورتحساب نسخه‌دار با شماره‌گذاری قانونی متناسب با بازار هدف، رسید استرداد، مالیات و تاییدیه مشتری.
3. اتصال **مجاز و عملیاتی** پرداخت، وب‌هوک امضاشده، idempotency و تطبیق واقعی با صورت‌حساب PSP؛ بدون ذخیره PAN/CVV یا شبیه‌سازی پرداخت موفق.
4. سیاست AML/KYC و مالیات متناسب با کشور و مجوز فعالیت، دریافت و انتقال وجه بین کشورها و منع کارمزد ارجاع غیرمجاز.
5. RBAC تفکیک وظایف تاییدکننده تراکنش و حسابدار، MFA اجباری، لاگ غیرقابل‌تغییر و جلوگیری از دستکاری ثبت‌های موجود.
6. قراردادهای مالی و نرخ تبدیل ارز تأییدشده، سیاست تسعیر، تسویه حساب بیمارستان و بازپرداخت؛ با تأیید حقوقی و مالی مستقل.
7. آزمون PostgreSQL production RLS، restore، خطا و امنیت زیرساخت.

**پذیرش:** ثبت سند با تأیید دوگانه و شواهد واقعی، گزارش‌های دقیق در حضور تراکنش‌های معکوس و وضعیت بانک، تست یکپارچه PSP مجاز، و ممیزی امنیت/حسابداری مستقل.

# بخش ۲۲ — وب‌سایت عمومی پنج‌زبانه MedTour AI

**دامنه تکمیل‌شده:** وب‌سایت اطلاع‌رسانی عمومی و غیرکلینیکی چندزبانه با ساختار مستقل، کاتالوگ محتوای منتشرشده، سئوی کنترل‌شده، مسیرهای عمومی چندزبانه و پیش‌نویس‌های فارسی، عربی، انگلیسی، پشتو و دری.

**مرز صداقت و امنیت:** این سامانه در محیط Alpha است؛ این محتوا قرارداد حقوقی معتبر، تأیید پزشکی، اثبات اعتبار بیمارستان/پزشک، تأیید ترجمه حرفه‌ای، یا مجوز دریافت اطلاعات پزشکی واقعی نیست. هیچ فرم عمومی برای گردآوری PHI وجود ندارد و «پرداخت / نوبت / ویزا / خدمات واقعی» در وب‌سایت عمومی تأیید نمی‌شوند.

## مسیرهای عمومی

- `/public/{tenant}/fa` — صفحه اصلی فارسی با جهت RTL
- `/public/{tenant}/ar` — صفحه اصلی عربی با جهت RTL
- `/public/{tenant}/en` — صفحه اصلی انگلیسی با جهت LTR
- `/public/{tenant}/ps` — صفحه اصلی پشتو با جهت RTL
- `/public/{tenant}/prs` — صفحه اصلی دری با جهت RTL
- `/public/{tenant}/{locale}/{slug}` — رندر سمت سرور از CMS، **فقط وضعیت published و فقط زبان/slug مجاز**؛ هر صفحه منتشرنشده 404
- `/public/{tenant}/sitemap.xml` — نقشه سایت همان Tenant، **فقط پس از آماده‌شدن کامل پنج زبان و فعال‌شدن سئو و HTTPS**
- `/robots.txt` — راهنمای خزنده با مسیرهای داخلی ممنوع؛ هر صفحه عمومی به‌صورت پیش‌فرض `noindex` است تا شرایط نمایه‌سازی برقرار شود.

پیش‌فرض انتخاب زبان به خود مسیر وابسته است. Next.js proxy هدر مورد استفاده root layout را فقط از مسیر `/public/{tenant}/{locale}` به دست می‌آورد؛ بنابراین HTML مطابق زبان با `lang=fa/ar/en/ps/prs/ps/prs` و `dir=rtl/ltr` پاسخ داده می‌شود. محتوای صفحه SSR و metadata هر زبان (عنوان، توضیحات، canonical، hreflang برای ترجمه‌های واقعاً منتشرشده و OpenGraph) از سمت سرور تولید می‌شود.

## صفحات آماده به‌عنوان پیش‌نویس

برای هر پنج زبان **۸ صفحه = مجموعاً ۴۰ پیش‌نویس**:

| slug | فارسی | English | العربية | پښتو | دری |
| --- | --- | --- | --- | --- | --- |
| about | درباره پلتفرم | About | من نحن | زموږ په اړه | درباره برنامه |
| services | خدمات هماهنگی | Services | الخدمات | خدمتونه | خدمات هماهنگی |
| process | مراحل هماهنگی | Process | الخطوات | پړاوونه | مراحل |
| faq | پرسش‌های متداول | FAQ | الأسئلة | پوښتنې | پرسش‌ها |
| contact | ارتباط | Contact | التواصل | اړيکه | تماس |
| privacy | پیش‌نویس حریم خصوصی | Draft privacy | مسودة الخصوصية | د محرمیت مسوده | محرمیت |
| terms | پیش‌نویس شرایط | Draft terms | مسودة الشروط | د شرطونو مسوده | شرایط |
| medical-disclaimer | سلب مسئولیت پزشکی | Medical disclaimer | إخلاء المسؤولية | طبي خبرتیا | سلب مسئولیت طبی |

این متن‌ها متعادل و **غیرپزشکی، غیرتبلیغ نتایج درمانی و فاقد قیمت/وعده خدمات واقعی** هستند. بخش `privacy` و `terms` صراحتاً **پیش‌نویس غیرقابل‌اتکای حقوقی** هستند. بدون بازبینی مستقل ترجمه، کارشناس پزشکی و حقوق بین‌الملل **نباید** منتشر شوند.

## راه‌اندازی محلی

```powershell
git pull origin main
docker compose up -d --build
docker compose exec api alembic upgrade head
```

1. به `http://localhost:3000/login` با کاربر admin وارد شوید. شناسه سازمان مثل `medtour-local` در نشست ثبت می‌شود.
2. در `/cms` دکمه «افزودن ۴۰ پیش‌نویس پنج‌زبانه» را انتخاب کنید. API `POST /api/v1/cms/public-site/bootstrap` فقط صفحات ناموجود را می‌سازد و هیچ محتوایی را خودکار منتشر نمی‌کند.
3. در `/cms` متن صفحات و نسخه‌های ترجمه را ویرایش و از مسئول مربوطه تأیید کنید. صفحات را به‌صورت جداگانه منتشر یا از انتشار خارج کنید.
4. با مسیرهایی مانند `http://localhost:3000/public/medtour-local/fa`، `/ar`، `/en`، `/ps` و `/prs` طراحی را ببینید. CMS manifest لیست صفحات قابل مشاهده، ترجمه‌های ناقص و وضعیت سئو را نشان می‌دهد.
5. تنها **بعد از تأیید واقعی محتوای حقوقی و ترجمه‌ها**، کلید `public_portal` در `/settings` می‌تواند به شکل `{"search_indexing_enabled":true,"legal_content_reviewed":true}` تنظیم شود. این فقط **خوداظهاری مدیر** است، نه اثبات تأیید حقوقی مستقل.
6. برای canonical/hreflang و sitemap تولید، `PUBLIC_SITE_URL=https://YOUR-VERIFIED-DOMAIN` (آدرس HTTPS واقعی متعلق به همان سایت) و `INTERNAL_API_URL=http://api:8000` برای رندر سمت سرور لازم است. بدون URL امن HTTPS، نتیجه همچنان `noindex` است. `PUBLIC_SITE_URL` در `docker-compose.yml` از محیط خوانده می‌شود.

## API و حداقل مجوزها

- `GET /api/v1/public/{tenant}/site-manifest`: صرفاً صفحات منتشرشده در هشت دسته تعریف‌شده؛ بدون اطلاعات بیمار، بیمارستان، مراجع درمان یا قیمت. `missing_translations`، `all_languages_complete`، `search_indexing_allowed` و flags صادقانه وضعیت حقوقی را برمی‌گرداند.
- `POST /api/v1/cms/public-site/bootstrap`: نقش admin، تکرارپذیر، **draft-only**، Tenant scope و audit.
- `GET /api/v1/cms/public-site/drafts/{id}`: خواندن متن کامل draft فقط admin همان Tenant.
- `PATCH /api/v1/cms/public-site/drafts/{id}`: ویرایش فقط draft، بازبینی قبل از publish مجدد الزامی؛ `extra=forbid` ورودی‌های اضافی را رد می‌کند.
- `PATCH /api/v1/cms/public-site/pages/{id}/unpublish`: لغو انتشار فقط admin؛ از لحظه پاسخ، مسیر عمومی 404 و در صورت ناقص شدن زبان‌ها وضعیت SEO غیرفعال می‌شود.
- مسیرهای اصلی `/api/v1/cms/pages` و `/publish` بدون تغییر معماری حفظ شده‌اند.

## تست و محدوده واقعی پذیرش

`backend/tests/test_section_22_public_website.py` پوشش: بی‌اجازه بودن draft و صفحات ناشناخته، tenant isolation، seed idempotency و حفظ ویرایش، سطح دسترسی admin/operator، صفحه منتشرشده و نبود ترجمه دیگر، اعتبارسنجی پوشش پنج زبان، شرایط noindex، unpublish فوری و محتوای plain-text غیرقابل اجرای React، محافظ‌های حقوقی فعال‌سازی سئو.

موارد **باقی‌مانده**: ترجمه توسط مترجم حرفه‌ای و ارزیابی فرهنگی/حقوقی کشورهای هدف، متون قانونی نهایی واقعی (نام سازمان و مسئول داده، شرایط بازپرداخت و شکایات، کوکی‌ها، سیاست انتقال فرامرزی)، تأیید اعتبار تجاری و بیمارستان‌ها، دامنه عمومی با SSL و Search Console، تست واقعی Accessibility/Lighthouse/Core Web Vitals و بررسی حقوقی و امنیت مستقل. قابلیت‌های پیشرفته چرخه تأیید و نسخه‌بندی CMS جزو بخش ۲۳ هستند.

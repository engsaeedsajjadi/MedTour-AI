# بخش ۳۹ — Implementation Phases (فازبندی اجرایی و معیار پذیرش)

## تحویل انجام‌شده
پنج فاز Gate 1 تا Gate 5 بر اساس `docs/ROADMAP.md` در فایل ماشین‌خوان `docs/section39_acceptance_gates.json` مشخص شده‌اند. اسکریپت `scripts/section39_gates.py` شواهد پذیرش فازها، وابستگی‌ها و ترتیبشان را ارزیابی می‌کند. فایل تست `backend/tests/test_section_39_delivery_gates.py` سناریوهای fail-closed را پوشش می‌دهد.

## فازهای اصلی
| فاز | محدوده | شرط ارتقا |
|---|---|---|
| Gate 1 | جداسازی Tenant، احراز هویت، ممیزی امنیت | RLS واقعی و تأیید مستقل |
| Gate 2 | پذیرش امن و هویت بیمار، اسناد، رضایت | تأیید هویت، امنیت ذخیره‌سازی و بازبینی بالینی |
| Gate 3 | پیام‌رسانی و عملیات چندکاناله | مجوز ارائه‌دهنده، رضایت، Webhook و Worker عملیاتی |
| Gate 4 | پزشک و بیمارستان، نوبت، سفر و مالی | تأیید شرکا، رزرو و تسویه قانونی واقعی |
| Gate 5 | SaaS، مانیتورینگ، DevOps و پذیرش نهایی | E2E، تست بار و نفوذ، بازیابی، تأیید حقوقی/بالینی |

## معیار وضعیت
- `accepted=false` تا زمانی که **تمام** الزامات آن فاز مدارک جداگانه با `approved: true`، `review_type: independent` و شناسه مرجع معتبر داشته باشند.
- Gate بعدی فقط در صورت پذیرش تمام Gateهای پیش‌نیاز قبول می‌شود.
- وجود Pull Request، تست نوشته‌شده یا مستندات به معنی گواهی Production نیست.
- فیلد `production_authorized` در خروجی ارزیاب عمداً همواره `false` است؛ اجازه استقرار باید در فرایند عملیاتی مستقلی صادر شود.
- در نسخه حاضر `evidence` خالی است؛ بنابراین **همه Gateها مردود/در انتظار شواهد هستند**.

## اجرای تست
از ریشه پروژه:
```powershell
git fetch origin
git switch feature/section-39-delivery-gates
python scripts/section39_gates.py
cd backend
python -m pytest -q tests/test_section_39_delivery_gates.py
```

**نکته:** خروجی اول به‌صورت مورد انتظار کد خروج ۱ می‌دهد، چون شواهد لازم هنوز ثبت نشده‌اند. این خطای ابزار نیست.

## وضعیت پروژه و اقدامات ضروری
- شاخه‌های بخش‌های ۲۸ تا ۳۸ هنوز PRهای مستقل و ادغام‌نشده هستند؛ قبل از ادغام باید dependencyها، سازگاری Migrationها و صحت CI بررسی شوند.
- هر فاز نیازمند مالک اجرایی، تاریخ واقعی، بودجه، گزارش آزمون، کنترل تغییر، مسئول تأیید و شواهد امضا‌شده در سیستم مورد اعتماد است.
- Gate 1 مهم‌ترین مانع فعلی است: اجرای RLS و tenant-principal routing واقعی، کنترل امنیت اطلاعات درمانی و تست نفوذ.
- هیچ استقرار با اطلاعات واقعی بیماران، WhatsApp واقعی، پرداخت یا رزرو خارجی در این تغییرات انجام نشده است.

## محدودیت
این تحویل «چارچوب اجرای فازبندی و کنترل پذیرش» است، نه تحقق فنی یا عملیاتی همه فازها. تغییرات تست نشده‌اند و هیچ Gate به‌صورت عملیاتی تأیید نشده است.

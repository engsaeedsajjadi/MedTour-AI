# بخش ۴۵ — Final Production Instruction / کنترل نهایی انتشار

## خروجی پیاده‌سازی‌شده
- `scripts/section45_release_gate.py`: اعلام ماشینی وضعیت نسخه Alpha و ممنوعیت استفاده از اطلاعات واقعی بیمار، AI پزشکی زنده، رزرو خارجی و دریافت وجه.
- `backend/tests/test_section_45_release_gate.py`: تضمین ثابت‌بودن وضعیت عدم پذیرش حتی با متغیر محیطی مدعی تأیید، و تست گیت قبلی `assert_safe_runtime('production')`.
- ابزار انتشار هیچ فرمان deploy یا روش دورزدن ندارد و عمداً exit code 1 برمی‌گرداند.
- این مرحله جایگزین مجوز حقوقی/بالینی/امنیتی یا قرارداد ارائه‌دهنده نیست.

## وضعیت حقیقی
برنامه `0.5.0-alpha` است، هنوز کد بخش‌های متعدد در PRهای مجزا قرار دارد و همه CIها، Migrationها، E2E، بار، امنیت و شواهد پذیرش نهایی تأیید نشده‌اند. بنابراین تکمیل بند ۴۵ به معنای فعال شدن Production نیست.

## برنامه اجرایی بعد از بخش ۴۵
1. تجمیع PRهای باز ۲۷ تا ۴۵ و بررسی تعارض و ترتیب Alembic؛ هیچ شاخه ناقص یا ناسازگار کورکورانه ادغام نشود.
2. رفع نقایص فنی واقعی همه بخش‌های ۱ تا ۴۵ و اجرای CI و تست‌های PostgreSQL/Redis با داده مصنوعی.
3. ساخت شاخه انتشار یکپارچه، ارزیابی انتشار و ارائه **یک دستور** دریافت نسخه قابل‌تست برای سیستم ویندوزی کارفرما فقط پس از وجود چنین شاخه‌ای.
4. تکمیل Telegram bot به‌صورت رسمی، با امنیت Webhook، onboarding حداقلی، ارجاع امن به پرتال و اپراتور، و کنترل رضایت؛ بدون پذیرش مدارک پزشکی در تلگرام.
5. تست مرحله‌ای با کارفرما در PowerShell و ارائه گزارش PASS/FAIL هر دستور.
6. فقط با تأیید واقعی مستقل حقوقی، پزشکی، امنیتی، عملیاتی و قراردادی می‌توان برای نسخه Production آینده برنامه‌ریزی کرد.

## آزمون موکول‌شده به مرحله یکپارچه‌سازی
```powershell
cd backend
python -m pytest -q tests/test_section_45_release_gate.py
cd ..
python scripts/section45_release_gate.py
```
اجرای آخر به‌طور عمدی ناموفق (Exit Code 1) است زیرا انتشار Production در این نسخه مجاز نیست.

**تکمیل پرامپت به معنی تکمیل همه قابلیت‌های عملیاتی نیست.** این تغییرات صرفاً الزامات کنترل انتشار امن بخش ۴۵ را اضافه می‌کنند.

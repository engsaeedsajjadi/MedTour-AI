# بخش ۴۴ — Final Acceptance / معیارهای پذیرش نهایی Enterprise

## تحویل واقعی این بخش
- `docs/section44_final_acceptance.json`: چک‌لیست ۱۵ کنترل نهایی در قالب ماشین‌خوان.
- `scripts/section44_acceptance.py`: شمارش شواهد معتبر، نمایش موارد غایب و جلوگیری از اعطای خودکار وضعیت تأیید.
- `backend/tests/test_section_44_final_acceptance.py`: تست رد شواهد خالی، خودتأییدی و دستکاری مجوز Production.
- هیچ کدام از این ابزارها جای بررسی اصالت اسناد، رأی بازبین امنیت/بالین یا مجوز فعالیت تجاری را نمی‌گیرند.

## معیارهای اصلی پذیرش
1. ادغام همه شاخه‌ها و CI سبز برای commit نهایی.
2. تست migration PostgreSQL، ارتقا، backup و rollback قابل بازیابی.
3. جداسازی چندمستأجری واقعی با RLS و roleهای DB محدود.
4. احراز هویت معتبر پزشک/بیمار و کنترل کامل دسترسی.
5. حقوق حریم خصوصی و انتقال بین‌المللی داده.
6. بازبینی بالینی و کنترل‌های محدودیت AI.
7. قرارداد قانونی و فنی ارائه‌دهندگان.
8. ارتباطات Telegram/WhatsApp رضایت‌محور با آزمون اتصال و شرایط ارائه‌دهنده.
9. تست E2E واقعی API و مرورگر.
10. آزمون بار و اندازه‌گیری SLO/SLI.
11. آزمون نفوذ مستقل.
12. Backup/Restore Drill.
13. Monitoring، alerting و runbook حادثه.
14. سهمیه‌های SaaS و فرآیند مالی امن.
15. آموزش تیم عملیاتی و پذیرش پایلوت.

## وضعیت در زمان ایجاد
**هیچ موردی به‌عنوان مورد قبول ثبت نشده است**. نتیجه واقعی این مرحله `NOT ACCEPTED` است و هیچ داده واقعی بیمار مجاز نیست.

## آزمون بعد از یکپارچه‌سازی
```powershell
git fetch origin
git switch feature/section-44-final-acceptance
cd backend
python -m pytest -q tests/test_section_44_final_acceptance.py
cd ..
python scripts/section44_acceptance.py
```
اجرای ارزیاب به‌صورت عمدی Exit Code 1 می‌دهد؛ ابزار به‌تنهایی اختیار صدور مجوز ندارد.
